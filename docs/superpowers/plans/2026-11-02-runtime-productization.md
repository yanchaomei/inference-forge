# 安装、服务接口与开源协作实现计划

目标：让新用户完成安装后即可启动已有生成引擎，通过常用SDK接入，并让贡献者找到任务、接口和验证方式。

本轮由用户“向vLLM等成熟仓库靠近，构建得更好”授权。实现与验证直接推进。

## 已选方案

- 将已生成的Qwen2引擎移入可安装的forge后端，原示例入口作为兼容入口。数值实现保持同一源码字节；历史结果按v0.2.0定位。
- `inference-forge serve MODEL_PATH`启动服务；`doctor --json`检查环境；`models`列出可直接服务的模型；`construct`调用既有构造流程，旧`--task`用法继续有效。
- 新服务支持OpenAI客户端所需的文本completions与chat completions子集、流式响应和标准错误。明确固定greedy与输出长度范围，不忽略不支持的采样/工具参数。原始token字段继续供既有评测使用。
- 英文首页+中文首页；安装、API、支持范围、贡献路径、Issue/PR模板、版本记录集中导航。当前公开视频和PDF入口继续可访问。

## 文件职责

`forge/cli.py`统一命令；`forge/protocol.py`处理请求和响应格式；`forge/serving.py`提供批处理HTTP服务；`forge/backends/qwen2/engine.py`保存原生成计算实现。既有`forge/server.py`与`forge/engine.py`继续作为构造种子。`examples/generated/batched`提供兼容导入入口。

## 实现顺序与验证

- [ ] 先添加命令行和真实HTTP协议回归，在远程CI确认缺失入口导致失败。
- [ ] 实现安装包内后端、统一CLI、OpenAI格式和聊天模板处理。
- [ ] 远程CI执行纯CPU任务测试、实际OpenAI SDK访问带测试引擎的HTTP服务，以及离开源码目录的wheel安装检查。
- [ ] GPU可用时执行真实模型的普通/流式聊天、并发与数值回归；保留环境失败，不把CPU协议通过当成GPU新性能结果。
- [ ] 完成中英文README、API/安装/支持矩阵、贡献文档和模板；核对命令与代码。
- [ ] 独立规格与质量复核，通过后合并发布。正式发布说明列明实际验证范围。

## 公共测试接口

测试穿过已安装命令行及实际HTTP路由，覆盖模型身份、聊天模板、非流式/流式文本、结束块、请求限制和错误状态。CPU测试使用确定的测试引擎验证协议与调度；真实模型验证在GPU执行。禁止用替代计时或CPU测试宣称新的推理性能。
