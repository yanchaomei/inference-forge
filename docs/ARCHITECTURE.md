# 系统说明

用户提供模型、设备、负载与约束。构造器保留可信执行工具，把完整运行时的 engine.py 和 server.py 交给 Coding Agent 修改。随后将固定评测代码与候选组装成快照，发到远程 GPU 执行。

参考模型与候选分进程运行。参考先产生 token、teacher-forced 概率与解码文本，候选再接受缓存续写和并发流式请求。通过正确性后，固定负载预热并重复测量。外层根据结果选择下一轮起点，失败、日志和源码身份均保留。

核心代码：

| 文件 | 职责 |
| --- | --- |
| forge/campaign.py | 本地 Agent 调用、候选装配、远程任务和反馈循环 |
| forge/engine.py | 可运行的 Qwen2 种子前向与 KV |
| forge/server.py | 请求调度、流式协议与诊断观测 |
| forge/evaluate.py | 独立参考、数值、文本与请求比较 |
| forge/pilot.py | 完整验收流程与数据记录 |
| forge/replay.py | 保留原失败签名的外部请求删除缩小 |

新生成的运行时不必继承现有框架的内部层次。当前只固定薄接口，保留实测需要的约束。源码身份和原始结果用于确认“实际测的是哪个候选”；测试通过仍只代表已覆盖范围。

未来优先推进强基线复现、真实失败回放与构造效率测量，再扩展模型和硬件。不会把多角色数量、日志数量或一次局部加速直接当作研究效果。
